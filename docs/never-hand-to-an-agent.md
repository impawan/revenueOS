# The decision I would never hand to an agent

I would never delegate the decision to commit the POC scope, timeline and success criteria to the customer. In this system the agent retrieves templates, drafts a plan and a handoff, and flags what it cannot know, but the Solution Architect accepts, edits or rejects, and that choice is a relationship and liability decision with asymmetric downside: a wrong yes becomes a broken promise to a bank or insurer, while a slow yes only costs days that the SLA watcher already measures. It also depends on context no event captures, such as the buyer's politics, delivery capacity this quarter and what Sales promised verbally, which is exactly why the draft carries `missing_from_sales` and `open_questions` instead of guessing. The same applies to the escalation on breach: the system tells Dana Whitfield, but a named person must own what happens next. Accountability for a customer-facing commitment has to sit with someone who can be asked why, and an agent cannot be that person.
